# v17/v18：设备占用保护、USB 音频崩溃调查与 E2x2 兼容修正

## 已确认的证据

- System 日志在 22:44:16 记录 BugCheck `0x0000010D`，参数 1 为 `5`，参数 3 为 `0x1200`；同一天还有一次相同参数类型的崩溃。
- Application 日志在 22:45:01 记录 Windows WER 分析桶：`0x10D_5_usbaudio2!UAWdfUsbDataPipe::SubmitQueuedBuffers`。
- 这说明 Windows USB 音频驱动在提交缓冲时发生了 WDF 内核错误。占用或设备重开可能是触发条件，但事件日志不能证明实际占用状态，也不能确认唯一根因。
- 转储位于 `C:\Windows\Minidump\101226-22031-01.dmp`，本次进程没有读取该文件的 Windows 权限，因此未进行完整堆栈分析。
- 原配置窗口勾选通道只更新列表；保存后会请求 DAW 重置并重开 KS 引脚。自动检测也会直接打开引脚。原打开流程未检查占用，且在占用失败后仍尝试其他格式及别名。

## v17 修复行为（历史）

- 读取 `KSPROPERTY_PIN_GLOBALCINSTANCES` 和 `KSPROPERTY_PIN_CINSTANCES`。只打开没有现有实例的 KS 引脚，即使驱动允许多个实例也不会与其他客户端并行打开该引脚。
- 在勾选新引脚、保存及自动检测前执行只读检查。占用时取消相应操作并弹窗“设备被占用，请释放后再试”。编辑正在由本驱动使用的已选引脚仍允许保存元数据。
- 使用按端点命名的进程间信号量，使本项目的不同 DAW 实例与配置程序不会同时打开同一端点；关闭引脚后释放占用。
- `KsCreatePin` 或过滤器打开返回占用错误时，立即停止全部格式、采样率、声道数量及别名重试。初始化部分失败会关闭先前打开的引脚。
- 保留初始化的真实 HRESULT，并传递给探测及 ASIO 错误处理。自动检测中途发现占用时终止任务、恢复控件、保留原设备缓冲，并显示提示。
- 先查询 WaveRT 映射能力。未声明支持的普通 KS 引脚直接使用已打开的数据包引脚，不提交 WaveRT 缓冲映射，也不为切换路径额外关闭、重开引脚。

旧驱动可能不实现实例数查询，此时仍需依赖打开返回的占用错误。检查与打开之间也可能有其他程序抢占设备。用户态保护无法捕获或修复设备驱动内部的 BugCheck；上述更改已经降低冲突和重复打开风险，真实硬件上的崩溃是否消除仍待验证。

## v18：E2x2 OTG 连接回归

用户安装 v17 后，E2x2 OTG 的 Loopback 1/2 报 `Could not create a KS pin ... (0x80070490)`。确认本机注册的 DLL 哈希与 v17 一致，PnP 中 E2x2 OTG 状态正常。

使用只读诊断对本机声卡的九个端点检查，未创建音频引脚：全局实例数属性均返回 `ERROR_NOT_FOUND`（`0x80070490`），局部实例数属性均正常返回 `CurrentCount=0, PossibleCount=1`。v17 在全局查询失败后提前退出，没有尝试可用的局部属性。这是 v17 引入的兼容性回归，不是声卡占用。

v18 将可选属性不存在或未实现视为“该查询不可用”，继续查询局部属性；完全不提供实例信息的老驱动仍走正常的 KS 打开流程，保留打开时占用错误的保护。同时纠正 v17 过严的实例判断：仅在 `PossibleCount > 0 && CurrentCount >= PossibleCount` 时阻止打开，避免把仍有剩余容量的多实例引脚误判为占用。权限拒绝、设备断开、截断响应和实际占满不会被当作可选属性缺失忽略。

新增模拟回归已先验证在 v17 逻辑下失败，再验证修复后通过，覆盖 E2x2 的“全局属性不存在/局部空闲”、局部占满、两类属性都缺失和多实例剩余容量。修复后，本机 E2x2 九个端点的只读 `access-check` 均从 `0x80070490` 变为 `S_OK`。这些检查只验证连接前的误拦截已消除，没有进行真实音频播放或复现黑屏。

只读诊断命令：`catalog_inspect.exe --access E2x2`。输出保存在开发构建目录的 `e2x2-access-v18.txt`。当前修复安装包为 `dist\AggregateAudio-v18-x64-Setup.exe`。
