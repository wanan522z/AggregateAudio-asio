# v19：KS 格式协商与通道自然排序

2026-10-13（Asia/Shanghai），用户报告更换 Donner Livejack 声卡后，ASIO 提示无法创建麦克风 KS Pin 2。宿主按 ASIO ABI 截取 128 字节，旧错误信息末尾的 HRESULT 没有显示。

## 原因与修复

只读检查确认，当时 Windows USB 音频驱动下 Donner 的输入、输出均空闲：全局和局部实例数均为 `CurrentCount=0, PossibleCount=1`，占用预检通过。输入只声明 24 位 PCM；`KSPROPERTY_PIN_DATAINTERSECTION` 返回 `WAVE_FORMAT_EXTENSIBLE`、48 kHz、双声道、32 位容器、24 位有效数据，`FormatSize=104`、`SampleSize=0`、`dwChannelMask=3`。输出还支持 16 位 PCM。

旧代码仅构造 float32、PCM32、packed PCM24、PCM16，且有效位数总等于容器位数，因此没有生成此输入要求的 24-in-32 格式。

v19 读取各引脚实际格式范围，先请求匹配的 KS 格式交集；验证返回的长度、类型、采样率、声道数、容器位宽、有效位数、帧步长和字节率，再原样使用驱动返回的格式创建引脚，包括驱动提供的通道掩码及 SampleSize。已知范围不会被混合成不支持的浮点/PCM 组合。协商属性缺失或协商格式不可用时保留旧格式回退，并增加 24-in-32、20-in-32、20-in-24、8 位 PCM 及驱动报告的其他有效位宽。支持低采样率和非标准范围边界的设备目录信息。

Extensible PCM 的有效数据左对齐，采集沿容器位宽换算，输出清零低位填充；8 位 PCM 使用无符号编码及 128 中点。占用保护继续在创建前和抢占失败时生效，不会在遇到占用后继续协商、格式或别名重试。错误信息现在以 `KS open failed 0x...` 开头，宿主截断时仍能看到原因码。

设备组内的端点按名称排序，英文大小写等价，数字按数值比较，例如 Playback 1/2、3/4、11/12。同一端点的声道按数字递增、保持相邻。UI 行索引仍映射到原来的端点和声道 ID，保存、勾选、刷新、折叠和滚动定位沿用这些 ID；不改写用户配置文件。

## 验证范围

MSVC x64 Release 编译，九项 CTest 模拟测试通过。新增回归覆盖 PCM 容器/有效位宽组合（32/24、24/24、32/20、16/16、24/22、8/8）的输入和输出、协商缺失的回退、协商后的抢占、左对齐填充与采样幅度、截断或错误的返回格式、非音频短范围之后的音频范围，以及 UI 排序后的勾选 ID 和相邻声道。

本轮检查期间，声卡由原来的 `Donner Livejack Usb Audio` Windows USB 接口切换为 `Livejack Audio Interface` 接口，后者返回的 24-in-32 格式 SampleSize 为 8，且不提供全局实例数属性。新版在当前接口实测输入、输出均可在 48 kHz 建立停止状态连接；E2x2 OTG 的九个端点、CX31993+MAX97220 的两个端点、USB PnP Sound Device 的两个端点也通过，共 15 个端点。所有引脚未启动、未提交采集或播放 IRP，未录制或播放音频。

原先 Windows USB 接口的格式协商证据已读取，但接口切换后未对其完成真机创建引脚验证。当前接口连接成功及模拟测试不能保证所有驱动、声卡或 DAW 的实际播放稳定性，也不能证明原内核黑屏问题已消除。

开发命令：`catalog_inspect.exe --formats Livejack`（只读）、`ks_open_check.exe Livejack`（显式创建停止状态连接）。发布安装包：`dist\AggregateAudio-v19-x64-Setup.exe`。关闭 DAW 和配置窗口后安装，再在面板中刷新设备；切换声卡驱动可能改变端点 ID，需要重新选择新接口的通道。

v19 安装包完成载荷 SHA256 校验，并通过隔离 HKCU 注册和工作区文件的完整安装测试：Unicode 注册路径、文件锁时拒绝升级/卸载、升级旧显示名、正常卸载、保留已转移到另一安装的注册。验证前后正式 ASIO 注册一致，未自动替换用户正在使用的安装。
